What I did: keeping AI output on-system

Problem

AI can generate UI code quickly, but the results often ignore design rules. Spacing, color and component styles drift, and the output can break in dark mode or on a phone.

Approach

I built the generated components on MDUI, a Material Design component library, so every widget uses the same components and theme. I designed the interface to be responsive and added light and dark mode support.

Result

Generated widgets look like they belong to the same design system and adapt to the user’s theme and screen size.

What I did: connecting a front end to a real API

Problem

The Spotify API needs users to sign in through OAuth before it returns data. A browser app can’t safely handle that flow on its own.

Approach

I split the app into two parts. A Node.js/Express server handles the OAuth sign-in and makes the API requests. The Angular front end calls my server and turns the results into search and browse views for artists, albums and tracks.

Result

Users sign in once and can move between search results, artist pages and albums without dealing with the API behind it.

What I did: turning video into court positions

Problem

A phone video is filmed at an angle, so a player’s position on screen doesn’t match where they actually stand on the court. Players far from the camera look closer together than they are.

Approach

I used computer vision to find players in each frame. Then I wrote custom geometry that uses the court’s known shape to convert each on-screen point into a real court position. Those positions drive a 3D tactical animation built in SwiftUI.

Result

Coaches and players can replay a possession as a clean tactical view instead of scrubbing through shaky footage.
